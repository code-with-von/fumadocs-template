Codeblocks are largely used in documentations when we need to exemplify our pieces of code (aka **code snippets**), and **Fumadocs** provide some nice integrations for allowing us to work with codeblocks.

Not only that - but also, **Fumadocs** provides an integration with **Shiki** and **TwoSlash**[^1] which allows an even deeper level of customization of code.

Below we provide as many different ways of passing any code snippet in documentation.

### 1. Basic code snippet

This is the most basic way of adding snippets to any **MDX** file. Any codeblock should follow the syntax below:

````markdown
```lang
your snippet goes here, following the language syntax
```
````

From this point ahead, any examples will assume `lang=js | ts` for a more complete set of examples, but most of what's showcased can be done with any other language, because iof **Shiki** support to most common programming languages[^2].


<Tabs items={['MDX', 'Output']}>
<Tab>
````mdx
```js
console.log('Hello World');
```
```` 
</Tab>
<Tab>
```js
console.log('Hello World');
```
</Tab>
</Tabs>

### 1. Type sensitive code snippets, with checks (**JavaScript + JsDoclets/TypeScript** only)

Type sensitive blocks should be used when we desire to specify:
1. Type definitions for objects, variables, constants or specify the expected type of values passed in a function
2. Provide a feedback over errors[^3] to list "wrong usage examples" and their expected errors

#### JavaScript + JsDoclets (preferred for documentation)

<Tabs items={['MDX', 'Output']}>
<Tab>
````mdx
```js twoslash title='js_docs_example.js'
// @filename: js_docs_example.js
// @ts-check
// @errors: 2322 2345 2554

/**
 * @param {number} a - The fist value of the addition
 * @param {number} b - The second value of the addition
 * @returns {number} The sum of a and b
 */
function add(a,b) {
  return a + b;
}

//case a (number, number) - correct use
add(5, 10);

// case b (number, string) - incorrect use
add(5, '10');

// case c (string, string) - incorrect use
add('5', '10');

// case d (string, number) - incorrect use
add('5', 10);

// case e (params missing) - incorrect use
add();
add(1);
```
````  
</Tab>
<Tab>

</Tab>

### 1. Shiki specific notation

**Shiki** has a set of notations that can be used to further customize the look and feel of codeblocks. The example below showcase a few of those possible notations


<Tabs items={['MDX', 'Output']}>
<Tab>
````mdx
```lang
// this code should be inside block code with a supported language
// highlight a line
<div>Hello World</div> // [!code highlight]

// highlight a word
// [!code word:Fumadocs]
<div>Fumadocs</div>

// diff styles
console.log('hewwo'); // [!code --]
console.log('hello'); // [!code ++]

// focus
return new ResizeObserver(() => {}) // [!code focus]
```
````
<Callout type='warning' title='NOTE'>
  You'll not see any formatting here, as if we define a specific formatting the code is not actually displayed, but it's 100% expected on your mdx file for you to see the proper formatting and coloring syntax when the param **lang** is passed on the example above, as displayed in the output, where lang was set to **jsx**!
</Callout>
</Tab>
<Tab>
```jsx
// this code should be inside block code with a supported language
// highlight a line
<div>Hello World</div> // [!code highlight]

// highlight a word
// [!code word:Fumadocs]

// diff styles

console.log('hello'); // [!code ++]

// focus

```
</Tab>
