There are some specific files that need to be changed at your needs to complete the process of customizing the provided template for your own use.

Those files are - listed relatively to the root of the project, in **alphabetic / location** order:

### 1. .vscode folder

This folder has a set of pre-defined settings, for:

1. suggested extensions used in the project
2. suggested workspace settings for the extensions used
3. suggested list of terminals to be executed when the workspace is loaded by your **IDE**

Files in this folder are not static, so you can change them as your need, based on your own **IDE** or **workspace** settings.

---

### 2. lib/shared.ts

This **sets** the title on the navigation bar of the **/docs** route and passes links your project to your **Github account**, **repository** and **branch**, based on the information provided for the **highlighted** lines below:

```ts title='shared.ts'
export const appName = "Your project Name"; //[!code focus]
export const docsRoute = "/docs";
export const docsImageRoute = "/og/docs";
export const docsContentRoute = "/llms.mdx/docs";

// fill this with your actual GitHub info, for example:
export const gitConfig = {
  user: "your-github-username", //[!code focus]
  repo: "your-project-repository-name", //[!code focus]
  branch: "your-project-main-branch", //[!code focus]
};
```

### 4. .env / .env.local

This file is never shared in any **Github repository**, but we are sharing an example of how your project variables (also know as **environmental variables**) should be defined.

```ini title='.env.example'
# --------------------------------------------------------------------------------------------------
# Posthog settings
# Those values should be obtained from Posthog dashboard in case you wish to work with your own Posthog account, and not the shared one provided by Infisical
# --------------------------------------------------------------------------------------------------
NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN=
NEXT_PUBLIC_POSTHOG_HOST=


# --------------------------------------------------------------------------------------------------
# Spotify settings
# This is the URL generated by https://spotify-github-profile.kittinanx.com after you successfully connect your account to this application
# --------------------------------------------------------------------------------------------------
NEXT_PUBLIC_SPOTIFY_URL=

```

To make use of this file, just create a new file with the name **.env** or **.env.local** at the root of the project, copy and paste the contents above e provide the necessary values for each variable.

### 5. .infisical.json

This file is never shared on any project and is created automatically when the project is successfully connected to [**Infisical**](https://infisical.com/), by following their instructions.

This file removes the need of any **.env\*** file, as long as the project is properly configured to use Infisical to inject the values expected as environmental variables into the project.

<Callout type='error' title='IMPORTANT'>
  ### **Connect the project with your Infisical project**
  To connect your project with **Infisical**, just run the command below:

  ```npm
  npm run inf:init
  ```

  and follow the instructions provided on the terminal where you used the command above.

  After a successful connection, a file similar to

```json
{
  "workspaceId": "infisical_workspace_uuid",
  "defaultEnvironment": "selected_env",
  "gitBranchToEnvironmentMapping": "value depends on your settings"
}
```
  should be created on your workspace.
  
  #### **Injecting the variables with Infisical (in local development)** [^1]

  To inject **environmental variables** using Infisical, just use the commands listed below, **depending on your use-case**:

  1. **during creation**
  ```npm
  npm run inf:dev
  ```
  2. **testing production before deployment** (you have to execute both commands, one after the other has finished the process and not them at the same time)
  ```npm
  npm run inf:build
  npm run inf:start
  ```

  ---

  #### **Injecting the variables with Infisical (in deployment)** [^1]
  For deployment, follow **Infisical** guides.
</Callout>

### 6. biome.json

This project uses **BiomeJs** as the main linter - so this file is created automatically when the project is bootstrapped from scratch.

This file sets linting and formatting rules which are not supported by **.editorconfig**.

You can modify the rules proved here based on your needs.

<Callout type='warn' title='ATTENTION'>
  In case you don't like using **BiomeJs** as your linter / formatter, you can replace for what you like to you, but you'll have to make all other changes needed for your **preferred** linter to work properly.

  Now if you are new to **BiomeJs** and is willing to give a try (or even keep the file provided in this template as it is), it's **strongly advised** that you check [biome's documentation](https://biomejs.dev/).
</Callout>

### 7. package.json

As in any **NodeJs** project, this file specifies definitions for your project.

The current file provided in this project, makes references to the **cloned project** and it's **dependencies**, **listed commands** and other configurations that can (or my need to be) passed into this file.

This file can be changed based on your needs, as long as you know **what**, **why** and **where** those changes are being applied.
