  ### Before you begin
    The contents of this section is placed inside the **02-file-structure** folder, which is part of the **content/docs** folder.

  You can delete the folder **02-file-structure** as it should not part of your project!
  - [x] another option is to add the **permission: dev** to the **YAML front matter** in all files from this folder, to keep them as a reference for your project (recommended)
  
  This folder is just here to help you understand how the documentation structure works.
</Callout>

Regardless of how many files your final project needs, here we have a reasonable example on how to structure your documentation project, when using this template. **The name of the files/folders are fictional and does not match the actual project you are creating or the names provided in the project**!

## Files/Folder List [step]

The list of files below exemplifies the expected structure of your documentation project **if** you are using this template.

<Callout type='error' title='IMPORTANT'>
  - **The folder structure below is only a reference. It is not exhaustive or static**, which means you can:
    - add files if you need
    - remove files if you don't need them
    - rename files if you want to
    - change/edit the code when necessary

  Just **remember** that:
  1. changes on the files listed here, should be done based on the required knowledge to change them
  1. files not listed here **can still be changed**, but any changes done are **at your own risk** and **knowledge-based** on the **tech-stack** required for using this template
  1. Files listed below are relative to the root level of the project you are creating from this template and names may not match exactly the ones you will find in your project when cloned
  1. `...` means that **other** files or folders **may/can** exist under this concept and, regardless of the reason they exist, they were not listed to avoid overflowing information
  1. `*` after a file/folder name means that if you are using that file/folder, it should not be renamed - the actual file/folder does not contain the `*` character, as it's being added here just as an indicator that the file/folder should not be changed in the codebase
  1. `ts`, `js`, `tsx` and `jsx` are being used **interchangeably** in this template as the template supports both file types without breaking the application
</Callout>
