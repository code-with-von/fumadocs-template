<Callout title='NOTE'>
  #### Before you begin
  You can delete the folder **04-examples** as it should not part of your project!
  - [x] another option is to add the **permission: dev** to the **YAML front matter** in all files from this folder, to keep them as a reference for your project
  
  This folder is just here to help you understand how the documentation structure works.
</Callout>

In this section we'll showcase the possible ways to structure the codebase for files placed directly on the **root level** of the folder **content/docs** (or their subfolders).

Remember that:

- [x] Files always take precedence over folders, when folders are used, that means files will always be displayed at the **top of the list** in the sidebar (exception for the **index.mdx**, when visible)
- [x] There won't be explanation or example on how to construct the **mdx** files that compose the documentation / folder structure presented with the examples. 

In case of doubts over how to construct those files, the [official documentation](https://www.fumadocs.dev) is always the best path to follow or have a look on other files of this project. 

<Callout type='error' title='IMPORTANT'>
This project never had any intentions of covering the whole official documentation, but to provide the template and structure that **I** use in my documentation projects!
</Callout>

> In order to have a **preview** on how each example provided here would behave, just try out interacting with the **documentation navigation bar**, expanding the **Preview** item added to each provided example!
>
> Each **Preview** folder is **nothing more than** a simulation of what is expected if the same **filesystem** was created inside **content/docs** folder, which is where the listed files on each example should be stored!
